# Oracle implementation

Python oracle for Nous: a Hugging Face baseline and a NumPy implementation of the LLM forward pass. It serves as the reference for validating the C++ engine and produces the traces that viewers consume.

> Status: Phase 0 (Foundations). See the ALICE project board for the current sprint.

## Requirements

- macOS or Linux
- Python 3.12 (enforced by `scripts/check_env.py`; see `.python-version`)

## Setup

```bash
    cd oracle
    python3.12 -m venv .venv
    source .venv/bin/activate

    python -m pip install --upgrade pip pip-tools
    pip-sync requirements.txt requirements-dev.txt
```

Then verify the environment:

```bash
    python scripts/check_env.py
```

The script prints the Python, PyTorch and Transformers versions and the available device (`cuda`, `mps` or `cpu`). Numerical validations always run on CPU in fp32.

## Managing dependencies

Edit the `.in` files only; the `.txt` files are generated by `pip-compile`.

```bash
    pip-compile --generate-hashes requirements.in -o requirements.txt
    pip-compile --generate-hashes requirements-dev.in -o requirements-dev.txt
    pip-sync requirements.txt requirements-dev.txt
```

`requirements-dev.in` constrains its versions to `requirements.txt` (`-c requirements.txt`), so both files always agree.

## Reproducibility check

Recreate the environment from scratch and compare:

```bash
    pip freeze > before.txt
    deactivate && rm -rf .venv
    python3.12 -m venv .venv && source .venv/bin/activate
    python -m pip install --upgrade pip pip-tools
    pip-sync requirements.txt requirements-dev.txt
    pip freeze | diff before.txt -
```

No output from `diff` means the environment is identical.

## Platform notes

The `.txt` files were compiled on macOS (Apple Silicon). PyTorch wheels differ on Linux (CUDA), so compile the requirements on Linux before using this oracle there.
